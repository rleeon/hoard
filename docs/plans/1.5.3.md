# 1.5.3 — UX polish: errores limpios, Modo Automático, blacklist, sidebar pulida

> Cuarto ciclo después del overhaul de detección. Foco: pulir lo que
> el usuario tropieza en el día a día. Errores que se leen como JSON
> de Rust, server upgrade que sólo copia comando, juegos detectados
> sin save que no se pueden descartar, sidebar que se siente cruda,
> sin indicador de uso de cuota. Y rename del "Configurar todo" a un
> **Modo Automático** que sea un toggle persistido (no acción
> one-shot), con cascada controlada hacia auto-restore.
>
> Plan único fuente de verdad. Log vivo en
> [`1.5.3-log.md`](1.5.3-log.md). Si te desvías, actualiza este
> archivo primero.

---

## §0. Diagnóstico actual (post-1.5.2)

1. **Errores del updater son crudos.** `apply_desktop_update`
   (`crates/hoard-desktop/src/commands/updates.rs:260`) devuelve un
   `Result<_, String>` con mensajes técnicos como
   `"no installer asset for this platform in release v1.5.2. Assets:
   hoard-1.5.2-linux-x86_64.tar.gz, hoard-1.5.2-linux-x86_64.tar.gz.sha256"`.
   La UI los muestra interpolados en un toast
   (`UpdateConfirmModal.svelte:67`) con `toastError(...)` que recibe
   un único string. El usuario quiere un **bloque visual único**
   (modal/dialog) con título resumen ("Error de actualización") y
   un cuerpo expandible con el detalle técnico.

2. **Server upgrade sólo copia comando.** En Linux con servidor
   local, el comando Tauri `apply_server_update`
   (`crates/hoard-desktop/src/commands/updates.rs:497`) ya existe y
   usa `pkexec sh -c "hoard-server upgrade"`. Está cableado en
   `Settings.svelte` (línea 177-200) pero **no** en el
   `UpdateConfirmModal` que abre desde la sidebar alert button: ahí
   sólo se ofrece copiar comando al portapapeles. El usuario quiere
   el botón ejecutable también en ese modal.

3. **Sin forma de descartar juegos detectados sin ruta.** Cuando un
   juego aparece detectado pero sin `found_paths` (ej. Terraforming
   Mars, Lethal Company), `Library.svelte` muestra el badge "Sin
   partidas aún" pero no hay botón rojo para borrarlo. La detección
   lo regenera en cada scan. **No existe API de "ignorar slug"**.

4. **Botón Magic es one-shot, no toggle.** `App.svelte:255-264` →
   `runMagicSetup()` ejecuta scan + track + boot agent una vez. No
   hay scheduling persistido. El usuario lo quiere convertir en un
   **toggle on/off** (verde / rojo) persistido en `Prefs`, con
   cascada: al activar Modo Automático ⇒ activar auto-restore; al
   desactivar Modo Automático ⇒ auto-restore queda como esté
   (independencia hacia abajo). Y un scheduler que re-escanea cada
   X tiempo cuando el toggle esté ON.

5. **Sin indicador de uso de plan.** El server ya expone
   `storage_used_bytes` y `storage_quota_bytes` en
   `/v1/auth/whoami` (`crates/hoard-server/migrations/0001_users.sql`),
   y el cliente ya tiene `refreshQuota()` con polling 30 s
   (`stores/auth.ts:60`). Falta cablearlo en la sidebar como:
   "Local" si `is_local_server`, barra 0-100% si nube.

6. **Sidebar y frame se sienten crudos.** Aside `w-60 border-r`
   zinc-800/950 sin sombras ni separadores, items con hover
   básico. El user quiere "más bonito, acorde al sistema". Las
   decoraciones de ventana son nativas
   (`tauri.conf.json: "decorations": true`) — **mantenemos
   nativas, polish va en el contenido**. Custom titlebar queda
   fuera de scope (rompe macOS/Windows tradicionales y arriesga
   regresiones por SO).

## §1. Objetivos no-negociables

1. **Errores estructurados con dialog único** (título + body
   expandible) para los flujos del updater (desktop + server) y
   reusables en otros flujos que hoy hacen `toastError(error)` con
   strings crudos.

2. **Botón "Actualizar servidor" en el `UpdateConfirmModal`** —
   ejecutable vía el comando Tauri ya existente
   (`apply_server_update`), con fallback "copiar comando" cuando el
   server no es local (remoto) o cuando el OS no es Linux.

3. **Blacklist de juegos detectados** con UX claro:
   - Botón rojo en card de "Sin partidas aún" (también en cards
     con paths pero sin tracking, para uniformidad).
   - Modal de confirmación con checkbox **"Añadir a blacklist
     permanente"** (no marcado por defecto).
   - Sin check ⇒ descarte de sesión (filtro UI in-memory).
   - Con check ⇒ persistir en CliState (`ignored_slugs`), filtrar
     en `list_detected_games`. Reactivable desde Settings.

4. **"Modo Automático" toggle** (rename de Magic):
   - On (verde) ⇒ scheduling de re-scan periódico + auto-restore
     activado en cascada.
   - Off (rojo) ⇒ scheduler detenido. **Auto-restore queda como
     esté** (no se desactiva por cascada inversa).
   - Persistido en `Prefs.automatic_mode: bool` (default false).
   - i18n en 8 locales: `automatic.title`, `automatic.toggle_on`,
     `automatic.toggle_off`, etc.

5. **Indicador de uso de plan** encima del toggle Modo Automático
   en la sidebar:
   - `is_local_server: true` ⇒ texto "Local" con icono `Server` /
     `HardDrive`.
   - `is_local_server: false` ⇒ barra horizontal de progreso
     (`bg-emerald-500` fill) con label `"{used} / {total}"` y
     porcentaje. Color cambia a `amber` >75%, `rose` >90%.

6. **Sidebar pulida sin custom titlebar**:
   - Mejor jerarquía visual (gradiente sutil, sombra interior en
     border, espaciado, micro-animación al pulsar nav).
   - Clases CSS por OS via `platform()` de Tauri si aporta
     (`.is-linux`, `.is-mac`, `.is-windows`) — opcional, sin
     romper compat.
   - Decoraciones nativas intactas (`decorations: true`).

## §2. Anti-objetivos

- **No** custom titlebar (los traffic-lights de macOS, los
  botones min/max/close de Windows). Justificación: arriesga
  regresiones cross-OS y el user pidió "acorde al sistema" —
  decoraciones nativas son lo más acorde.
- **No** cambiar el modelo de cuota del server. Sólo render del
  dato ya disponible.
- **No** tocar la pipeline de detección (`detect_all` etc.). 1.5.3
  es 100% UX y persistencia ligera (Prefs / CliState).
- **No** añadir nuevos endpoints al server. Todo cliente-side y
  agent-side.
- **No** rebrandear "Magic" en CHANGELOG histórico — el rename
  empieza en 1.5.3, las versiones previas siguen citando Magic.

## §3. Visión: cómo se siente la app después de 1.5.3

1. Updater de cliente falla → un modal único aparece con título
   "Error de actualización" + un párrafo legible + un toggle
   "Ver detalles técnicos" que muestra el mensaje raw. El user
   cierra con un botón y sigue.

2. Sidebar bell → modal updater muestra dos botones: "Actualizar
   cliente" (verde) y, si hay update del server, "Actualizar
   servidor" (verde también). El botón server lanza `pkexec` y
   muestra outcome (`UpgradedAndRestarted` con toast).

3. Library scan detecta Lethal Company sin save → la card tiene
   botón rojo a la derecha. Click → modal "¿Eliminar este juego?"
   con checkbox "Añadir a blacklist permanente". El user marca y
   confirma. El juego desaparece y no vuelve en futuros scans
   hasta que lo saque de la blacklist en Settings → "Juegos
   ignorados".

4. Sidebar muestra un toggle grande "Modo Automático" debajo de
   las nav items. Apagado (rojo) ⇒ nada hace. Activado (verde) ⇒
   auto-restore se enciende automáticamente, y un scheduler corre
   `runMagicSetup`-equivalente cada N horas en background.

5. Encima del toggle, una barra "Uso del plan" que muestra "Local"
   (con icono) si el server es local, o "3.4 / 100 GB · 3%" con
   barra emerald si está en nube. Se actualiza cada 30 s (ya
   existe `refreshQuota`).

6. Sidebar y frame se ven más cuidados: separadores tenues,
   sombra interior, hover suave con transición, espaciado
   aireado. Decoraciones de ventana nativas.

## §4. Arquitectura objetivo

### §4.1 Error envelope estructurado

Tipo nuevo en `crates/hoard-desktop/src/commands/updates.rs` (y
reutilizable en otros comandos):

```rust
#[derive(Debug, Clone, serde::Serialize)]
pub struct AppError {
    pub title: String,        // i18n key OR resolved string
    pub body: String,         // i18n key OR resolved string
    pub detail: Option<String>, // technical message, oculto bajo "ver detalles"
}
```

`apply_desktop_update` y `apply_server_update` devuelven
`Result<Outcome, AppError>`. El no-asset case produce:

```rust
AppError {
    title: "updates.error.title".into(),       // "Error de actualización"
    body: "updates.error.no_installer".into(), // "No se encontró un instalador para tu plataforma en esta versión..."
    detail: Some(format!("Assets: {}", assets.join(", "))),
}
```

UI nueva: componente `lib/components/ErrorDialog.svelte`:

```svelte
<Modal open={open} title={$_(error.title)}>
  <p>{$_(error.body)}</p>
  {#if error.detail}
    <button onclick={toggle}>Ver detalles</button>
    {#if shown}<pre>{error.detail}</pre>{/if}
  {/if}
</Modal>
```

Helper `store/error_dialog.ts` con `showError(error: AppError)`
para que cualquier componente lo invoque.

### §4.2 Server upgrade en `UpdateConfirmModal`

Hoy `UpdateConfirmModal.svelte` (línea 75-82 según recon) en la
rama `isServer` copia `"sudo hoard-server upgrade"` al portapapeles.
Cambio:

```svelte
{#if isServer}
  {#if canRunServerUpgrade}
    <Button onclick={runServerUpgrade}>Actualizar servidor</Button>
  {:else}
    <Button onclick={copyCommand}>Copiar comando</Button>
  {/if}
{/if}
```

`canRunServerUpgrade = $auth.user?.is_local_server === true &&
platform() === "linux"`. El comando Tauri `apply_server_update` ya
existe; sólo se cablea.

### §4.3 Blacklist de juegos detectados

CliState (`crates/hoard-agent/src/state.rs` o donde viva) gana:

```rust
pub struct CliState {
    // ... existente
    #[serde(default)]
    pub ignored_slugs: HashSet<String>,
}
```

Comandos Tauri nuevos en `crates/hoard-desktop/src/commands/library.rs`:

```rust
#[tauri::command]
pub async fn ignore_detected_game(slug: String, state: State<'_, ...>) -> Result<(), AppError>;

#[tauri::command]

#[tauri::command]
pub async fn list_ignored_slugs(state: State<'_, ...>) -> Result<Vec<String>, AppError>;
```

`list_detected_games` filtra `if cli_state.ignored_slugs.contains(&game.slug) { continue; }`.

Library.svelte: nueva card action "Eliminar" (icono Trash rojo) en cards
detectadas no-tracked (con o sin found_paths). Modal `IgnoreDetectedModal.svelte`:

```svelte
<Modal title={$_("library.ignore_title")}>
  <p>{$_("library.ignore_body", { values: { name } })}</p>
  <label>
    <input type="checkbox" bind:checked={addToBlacklist}>
    {$_("library.ignore_blacklist_check")}
  </label>
  <Footer>
    <Button onclick={cancel}>Cancelar</Button>
    <Button variant="danger" onclick={confirm}>Eliminar</Button>
  </Footer>
```

- Sin check ⇒ `sessionDismissed.add(slug)` (estado Svelte memory).
- Con check ⇒ `api.ignoreDetectedGame(slug)` ⇒ persistido.

Settings.svelte → nueva sección "Juegos ignorados" con lista de
slugs blacklisted y botón "Reactivar" por cada uno (llama
`unignoreDetectedGame`).

### §4.4 Modo Automático

`Prefs` (`crates/hoard-agent/src/prefs.rs:74`) gana:

```rust
#[serde(default)]
pub automatic_mode: bool,        // default false
#[serde(default = "default_scan_interval_hours")]
pub automatic_scan_interval_hours: u32,  // default 6
```

Comando Tauri `set_automatic_mode(enabled: bool)`:
- Persiste `automatic_mode = enabled`.
- Si `enabled` ⇒ persiste `auto_restore = true` (cascada hacia abajo).
- Si `!enabled` ⇒ NO toca `auto_restore`.
- Si `enabled` ⇒ arranca o reinicia un scheduler Tokio
  (`tokio::time::interval`) que llama a una versión interna de
  `runMagicSetup` cada `scan_interval_hours`.
- Si `!enabled` ⇒ detiene el scheduler.

UI: el botón Magic actual (`App.svelte:255-264`) se sustituye por:

```svelte
<button class={mode ? "bg-emerald-500" : "bg-rose-500"} onclick={toggle}>
  <Sparkles /> {$_("automatic.title")} · {mode ? "ON" : "OFF"}
</button>
```

Visualmente: pildora ancha al pie del aside, color verde / rojo,
con un indicador de animación (pulse) cuando hay scan corriendo.

i18n: rename keys `magic.*` → `automatic.*` en los 8 locales:
`automatic.title` ("Modo automático" / "Automatic Mode" / etc.),
`automatic.toggle_on`, `automatic.toggle_off`, `automatic.scanning`,
`automatic.help_tooltip`.

### §4.5 Indicador de uso de plan

Sobre el toggle Modo Automático, un mini-bloque:

```svelte
{#if isLocal}
  <div class="...">
    <HardDrive size={14} />
    <span>{$_("sidebar.plan_local")}</span>
  </div>
{:else}
  <div>
    <div class="text-xs">{format(used)} / {format(quota)}</div>
    <div class="h-1 bg-zinc-800 rounded">
      <div class="h-1 bg-emerald-500 rounded" style="width: {percent}%" />
    </div>
    <div class="text-xs">{percent}%</div>
  </div>
{/if}
```

Colores progresivos: emerald <75%, amber 75-90%, rose >90%.
Reactivo a `$auth.user.storage_used_bytes / storage_quota_bytes` ya
hidratados por `refreshQuota`.

## §7. Prompts ejecutables

### P-D153-0 — ADR 0012

Redacta `docs/decisions/0012-ux-polish-and-automatic-mode.md`
formato del ADR 0011 (Status / Context / Decision / Consequences /
Alternatives considered). Status: Accepted, 2026-05-19.

Context cubre las seis grietas del §0. Decision lista las seis
piezas del §4 (error envelope, server upgrade button, blacklist,
Modo Automático con scheduler, indicador cuota, sidebar polish).

Consequences: persistencia adicional en Prefs y CliState,
scheduling background, dependencia del flag `is_local_server` ya
calculado, decoraciones nativas mantenidas.

Alternatives rechazadas: (a) custom titlebar (riesgo cross-OS),
(b) blacklist por defecto (rompe re-scan), (c) auto-restore
desactivado al apagar Modo Automático (rompe expectativa de
"independencia hacia abajo"), (d) cuota como porcentaje sin
barra (menos legible), (e) errores en línea sin modal (no
escalable a errores largos).

Sin código. Marca P-D153-0 DONE.

## §8. Riesgos

- **Scheduler tokio en Tauri commands** — la handle del scheduler
  debe vivir en un `State` managed para sobrevivir entre
  invocaciones. Test manual: activar Modo Automático, esperar el
  intervalo, verificar log de scan.
- **Renombrar keys i18n** — si algún componente usa `$_("magic.idle")`
  fuera de App.svelte, romperá silencioso (svelte-i18n no falla
  en compile-time). Grep exhaustivo antes de borrar las viejas.
- **Filtrado de ignored_slugs en `list_detected_games`** debe
  correr DESPUÉS de la detección completa, no antes — sino el
  walker no se beneficia del install_dir del slug ignorado para
  detectar otros juegos en el mismo dir (improbable, pero
  conceptualmente).
