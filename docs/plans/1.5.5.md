# 1.5.5 — Conflict-aware restore + skip mientras juegas + UI Settings ampliada

> Sexto ciclo. Pule el Modo Automático tras feedback del user sobre
> 1.5.4. Cuatro grietas reales:
>
> 1. **`restore_files_into` siempre prefiere local** (ADR 0013).
>    Multi-dispositivo se rompe: subes save bueno desde A, abres juego
>    en B sin sync previo (juego escribe placeholder vacío), tick
>    automático ve bytes distintos y *conserva el placeholder local*.
>    Pierdes el save bueno sin saberlo.
> 2. **Sin pausa mientras juegas**: auto-restore podría sobrescribir
>    saves que el juego tiene abiertos en este momento. Hoy estamos a
>    salvo solo porque (a) auto-restore solo copia missing y (b) el
>    juego rara vez escribe sobre lo descargado. Pero la regla nueva
>    de conflict resolution lo hace urgente.
> 3. **Primer tick tarda 6h**: al togglear Modo Automático no pasa
>    nada visible hasta el siguiente intervalo. El user no nota que el
>    sistema esté funcionando.
> 4. **El intervalo no se puede configurar desde UI**, sólo editando
>    `prefs.json` a mano. Y al togglear Modo Automático no hay feedback
>    visual de éxito.
>
> Plus: limpieza PT locale (mismo issue que ES en 1.5.4, dejado
> deliberadamente fuera), reemplazar `navigator.userAgent` por
> `@tauri-apps/plugin-os` oficial, smoke test i18n.
>
> Plan único fuente de verdad. Log vivo en
> [`1.5.5-log.md`](1.5.5-log.md).

---

## Decisiones del user (recogidas antes de planificar)

| Pregunta                                            | Respuesta                                                                                                         |
| --------------------------------------------------- | ----------------------------------------------------------------------------------------------------------------- |
| Cómo resolver conflicto (mismo path, bytes distintos) | Mtime decide quién gana. Si remoto gana, copia local a `.hoard-conflicts/<save>/<ts>/<rel>` antes de sobrescribir. |
| TTL para `.hoard-conflicts/`                        | 14 días. Limpieza al inicio de cada tick automático.                                                              |
| Qué pasa al activar Modo Automático                  | Restore inmediato + backup-sweep inmediato. Sin esperar 6h.                                                       |
| Pausa mientras juegas                                | Sí. Primero proceso del juego corriendo (ya hay `slot.is_running`). Si no hay match, skip si dir mtime <5min.    |
| Hook al cerrar juego                                | Polling cada 10s, **solo para saves cuyo juego está actualmente corriendo**. Antiguos siguen por el tick.       |

Estas decisiones constan también en ADR
[0014](../decisions/0014-conflict-aware-restore-and-game-activity-skip.md).

### P-D155-1 — Conflict-aware restore con `.hoard-conflicts/` + TTL

`hoard-agent/src/agent.rs`:

- `RestoreStats` añade `conflicts_resolved_remote: usize`,
  `conflicts_resolved_local: usize`, `conflicts_backed_up: usize`.
- `restore_files_into(target, source, conflict_backup_dir: Option<&Path>)`:
  - Bytes iguales → skip.
  - Bytes distintos → comparar mtime:
    - `local_mtime > remote_mtime` → local wins, no se toca, bump
      `conflicts_resolved_local`.
    - `remote_mtime > local_mtime` (o iguales con diferencia <1s) →
      remoto gana. Si `conflict_backup_dir` es `Some`, mover local
      a `conflict_backup_dir/<rel>` antes de sobrescribir. Bump
      `conflicts_resolved_remote` y `conflicts_backed_up`.
- Nueva función `cleanup_old_conflicts(conflict_root: &Path,
  retention: Duration)`: walk subdirs por timestamp, borrar los
  más viejos.
- `run_auto_restore` calcula `conflict_backup_dir` a partir de
  `state_dir/conflicts/<save_id>/<ts>/`, pasa a `restore_files_into`,
  y al final llama `cleanup_old_conflicts`.
- `AgentEvent::SaveConflictsBackedUp { save_id, count,
  conflict_dir }` se emite si `conflicts_backed_up > 0`.

`hoard-agent/src/prefs.rs`:

- Añadir `#[serde(default = "default_conflict_retention_days")] pub
  conflict_retention_days: u32` con default 14.

Tests:

- `restore_files_into_remote_wins_when_remote_newer`
- `restore_files_into_local_wins_when_local_newer`
- `restore_files_into_backs_up_local_before_overwrite`
- `cleanup_old_conflicts_respects_ttl`

### P-D155-3 — Skip auto-restore si juego corriendo o save tocado <5min

`hoard-agent/src/agent.rs`:

- En `sweep_for_auto_restore`, antes de `spawn_auto_restore` para un
  slot, comprobar:
  1. `slot.is_running == true` → log debug + skip.
  2. `slot.is_running == false` y `slot.processes.is_empty()` (no
     hay process_name) → comprobar `local_path` mtime. Si <5min,
     skip.
- También guardar contra auto-restore en `handle_add` con la misma
  lógica.

`hoard-agent/src/agent.rs` (test):

- `sweep_skips_running_slot`
- `sweep_skips_recently_touched_when_no_process_match`

### P-D155-4 — Polling 10s solo para saves activos (GameStopped → backup)

Verificar que `process_poll` ya dispara `schedule_backup` con
`BackupReason::GameStopped` (agent.rs:1269). Ya existe. Asegurar:

- Cuando Modo Automático está ON y el juego cierra, el backup va
  por la ruta `BackupReason::GameStopped` igual que en modo manual.
- Si por alguna razón el slot no estaba siendo polled, añadir
  watchdog que registre slots con `is_running` al boot del scheduler
  para no perder transiciones.

Si tras inspección no hace falta nada, P-D155-4 = no-op (cerrado en
log).
