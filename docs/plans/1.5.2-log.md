### P-D152-2 — pathexpand Windows: registry + Saved Games + OneDrive-aware
Fecha: 2026-05-19  ·  Ejecutor: Opus  ·  Estado: DONE

Cambios:
- Añadida dep `winreg = "0.52"` bajo `[target.'cfg(windows)'.dependencies]` en `crates/hoard-agent/Cargo.toml`. No se promueve a `[workspace.dependencies]` — único consumer y Windows-specific. No se añade `windows-sys`: la ruta `SHGetKnownFolderPath` la sustituyen el registry de `User Shell Folders` (Documents/AppData/Local AppData) y la síntesis directa desde `%USERPROFILE%` (Saved Games, LocalLow), suficiente para los seis tokens del plan y evitando una crate enorme.
- Token nuevo `<winSavedGames>` mapeado a `home_dir().join("Saved Games")` bajo el brazo `(Os::Windows, _)`. En Linux/Mac el token se descarta vía el match (no se llega a sintetizar).
- Token nuevo `<winLocalAppDataLow>` mapeado a `home_dir().join("AppData/LocalLow")`. Ludusavi lo usa en un puñado de juegos que escriben al árbol IE-sandboxed; no aparece en `User Shell Folders` por lo que se sintetiza desde `%USERPROFILE%` directo.
- Helper nuevo `windows_known_folder(token) -> Option<PathBuf>`, `#[cfg(windows)]`, que abre `HKCU\Software\Microsoft\Windows\CurrentVersion\Explorer\User Shell Folders` para `winDocuments`/`winAppData`/`winLocalAppData` y `HKLM\...\Shell Folders` para `winPublic` (`Common Documents`) y `winProgramData` (`Common AppData`). Si la value existe, expande `%USERPROFILE%`/`%SystemRoot%` etc. y devuelve `Some(path)`. Stub `#[cfg(not(windows))] -> None`. Llamado al inicio de `expand_placeholder` cuando `os == Windows`; si devuelve None, cae al match basado en env vars (compat 100%).
- Función pública `expand_registry_path(reg: &hoard_manifest::ludusavi::RegistryPath) -> Vec<PathBuf>`. Versión Windows parsea `reg.key` (acepta `/` y `\`), valida hive en `HKEY_CURRENT_USER`/`HKEY_LOCAL_MACHINE` (acepta también los aliases `HKCU`/`HKLM`), abre la subkey, lee `reg.value` como string (default value si `None` / `""`), expande env vars `%FOO%` con lookup case-insensitive, y si el resultado contiene placeholders `<…>` recurre vía `expand_path(_, Os::Windows)`. Cualquier fallo (hive desconocido, key/value missing, value no-string) ⇒ `Vec::new()`. Stub `#[cfg(not(windows))]` siempre devuelve vec vacío.
- Helper privado `expand_windows_env_vars(&str) -> String` (Windows-only): walker char-by-char que sustituye `%NAME%` con la env var correspondiente, case-insensitive. Variables desconocidas se conservan literales para que un misconfig sea visible aguas arriba en logs.
- Docstring inline 1-2 líneas en cada token nuevo siguiendo el estilo del archivo.

Archivos tocados:

Notas / decisiones de ejecución:
- **`rusqlite` bundled justificado**: feature `bundled` compila sqlite C estáticamente. La crate es `cfg(windows)`-gated en prod, así que builds Linux/macOS no la incluyen jamás.
- **Mirror dev-dep no-Windows**: añadí `rusqlite` también como dev-dep cfg(not(windows)) porque el test `gog_parses_synthetic_sqlite` corre en Linux/CI y necesita instanciar una `Connection` para sintetizar el fixture. La función `gog_read_db` quedó gateada `#[cfg(any(windows, test))]` y `list_installed_gog_games` en no-Windows-no-test cae al stub `Vec::new()`. En no-Windows-prod la función pública siempre devuelve vacío (consistente con el contrato del plan), pero los tests sí pueden invocarla con `Os::Windows` y un `LOCALAPPDATA` sintético — ese es el patrón cross-platform que pedía el plan.
- **Patrón `os` vs `#[cfg(windows)]`**: Epic y GOG usan `if !matches!(os, Os::Windows) { return Vec::new(); }` en la función pública y leen filesystem/sqlite portable después; permite tests con fixtures Linux.
