RetroArch は、ゲーム内のセーブを `.srm` ファイルとして `saves` フォルダーに、ステートを `states` フォルダーに保存します。デバイス間で同期するには、RetroArch 内蔵の Cloud Sync を自分で用意した WebDAV サーバーと組み合わせるか、両方のフォルダーを見張るツールを使います。Hoard は後者を自動で行います。RetroArch を終了したときに両方のフォルダーをバックアップし、他のマシンに取り込み、すべてのバージョンを残し、EmuDeck の構成も理解します。

## RetroArch のセーブの保存場所

- **Windows：** `%APPDATA%\RetroArch\saves` と `\states`。専用フォルダーにインストールした場合は、`retroarch.exe` の横の `saves` と `states`。
- **Linux：** `~/.config/retroarch/saves`。Flatpak は `~/.var/app/org.libretro.RetroArch/config/retroarch/saves` を使います。
- **EmuDeck を入れた Steam Deck：** `~/Emulation/saves/retroarch/`。中の `saves` と `states` は実際のフォルダーへのリンクです。Hoard は `retroarch.cfg` を読んで、本当の行き先を突き止めます。
- **RetroDECK：** 既定では `~/retrodeck/saves` と `~/retrodeck/states`。
- **それ以外：** **Settings → Directory** に、RetroArch が実際に使っているフォルダーが表示されます。

## RetroArch が実際にセーブを書き込むタイミング

ここで多くの人がつまずきます。RetroArch はゲーム内のセーブをメモリに持ち、ゲームを閉じるか RetroArch を終了したときにだけ `.srm` を書き込みます。例外は **Settings → Saving → SaveRAM Autosave Interval** を設定している場合です。それまではディスクに何もないので、クラッシュやバッテリー切れで最後の書き込み以降がすべて失われ、どんな同期ツールも書かれていないセーブは運べません。

オートセーブの間隔を数秒に設定してください。そしてデバイスを替える前に、ゲームだけでなく **RetroArch を終了** してください。Hoard は RetroArch が閉じてからバックアップするので、書きかけのセーブをコピーすることはありません。Deck では、スリープは終了に数えられません。

## すべてのデバイスを同じ設定に

- **振り分けの設定。** **Settings → Saving** では、セーブとステートをコア名やコンテンツのフォルダーごとのサブフォルダーに振り分けられます。片方だけが振り分けていると、同期されたファイルは RetroArch が見ないフォルダーに入ります。どこでも同じ設定にしてください。
- **ROM のファイル名。** `.srm` は ROM と同じ名前になります。`Super Metroid (USA).sfc` のセーブは `Super Metroid (USA).srm` です。もう一台で ROM の名前が違えば、見つかりません。
- **同じコア。** 同じ機種用の二つのコアが、互いのセーブを読めるとは限りません。機種ごとにひとつ選んで、どこでもそれを使ってください。
- **ステートにはコアのバージョン。** ステートはコアのメモリのスナップショットで、別のバージョンでは読み込めないことがよくあります。通常のセーブにはこの問題はありません。

ステートにはもうひとつ落とし穴があります。ステートにはゲームのメモリが、セーブも含めて入っています。古いステートを読み込むと、次の `.srm` の書き込みでその古いセーブが戻ってきます。**Auto Load State** を使っているなら、ステートも同期して、最新のものが運ばれるようにしてください。

## RetroArch の Cloud Sync か、Hoard か

両方に公平に言うと：

- **RetroArch の Cloud Sync** は内蔵で、自分で運用するか借りた WebDAV サーバーとセーブやステートを同期します。Android や iOS でも動きますが、Hoard は今のところ動きません。ファイルのバージョンを独自に残す Nextcloud をすでに使っているならよく合いますし、スマートフォンも使うならこちらのほうが向いています。
- **Hoard** は WebDAV サーバーを必要としません。自動でバックアップと同期を行い、戻れるバージョン履歴を残し、単体のエミュレーターや PC ゲームもまとめて扱います。`saves` フォルダー全体をひとつの項目として扱うので、巻き戻すと中のすべてのゲームがその時点の状態に戻ります。確定する前に何が変わるかを表示し、現在のファイルは先に保存されます。

フォルダーごとにどちらか一方を選んでください。二つのツールが同じセーブを書けば、競合の元になります。

## Hoard で設定する

1. 各デバイスに Hoard をインストールし、同じアカウントでサインインします。
2. **ライブラリ** で RetroArch を追加します。セーブとステートが二つの項目として表示されます。
3. 上の設定をすべてのデバイスでそろえます。
4. 遊んで、RetroArch を終了し、もう一台で続けます。

家の中だけで完結させたいなら、PC か NAS で `hoard-server` を動かしてください。私たちのアカウントは不要、私たちへのテレメトリーもなく、私たちのサーバーを何も通りません。[Hoard をセルフホストする方法](/guides/self-host-hoard) を参照してください。

## よくある質問

### RetroArch にクラウドセーブはありますか？

はい。WebDAV サーバーが必要な Cloud Sync が内蔵されています。サーバーを運用したくない、バージョン履歴がほしい、単体のエミュレーターも使っている、という場合は Hoard が代わりになります。

### RetroArch のセーブが同期されなかったのはなぜ？

たいてい次の三つのどれかです。RetroArch がまだ `.srm` を書いていなかった（オートセーブの間隔なしで開いたままだった）、二台がセーブを別々のサブフォルダーに振り分けている、ROM の名前が違う。

### ステートも同期できますか？

はい。Hoard は `states` を独立した項目として追跡します。もう一台でステートが読み込めるかは、両方が同じバージョンのコアを使っているかどうかで決まります。

### EmuDeck や RetroDECK でも使えますか？

はい。Hoard は RetroArch の設定を読み、EmuDeck のリンクをたどって実際のフォルダーを見つけます。RetroDECK では、検出されなければ `~/retrodeck/saves` と `~/retrodeck/states` を追加してください。

### Android の RetroArch も同期できますか？

今のところできません。Hoard が動くのは Windows、macOS、Linux、Steam Deck です。
