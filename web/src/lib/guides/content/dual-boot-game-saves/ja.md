デュアルブートの PC では、同じゲームが二つの別々のセーブを持ちます。ひとつは Windows のユーザーフォルダーに、もうひとつは Linux の Proton プレフィックスの中に。Steam Cloud に対応したゲームならこの二つをつないでくれますが、それ以外はシステムを切り替えた最初の時点でずれ始めます。Hoard はこれを自動で同期します。同じアカウントで両方のシステムにインストールすれば、どちらを起動しても各ゲームのセーブがついてきます。

## なぜひとつのゲームにセーブが二つあるのか

ディスクは共有されていても、セーブフォルダーは別々です。

- **Windows では**、ゲームは `C:\Users\<あなた>` の下の `Documents`、`Saved Games`、または `AppData` フォルダーのどれかに書き込みます。
- **Linux では**、同じ Windows 用ゲームが Proton で動き、専用のプレフィックスの中に書き込みます：`~/.local/share/Steam/steamapps/compatdata/<AppID>/pfx/drive_c/users/steamuser/`、その後に同じ Windows のパスが続きます。

同時には決して動かない二つのシステムに、ひとつのセーブのコピーが二つ。最後にどちらで遊んでも、もう一方はそれを知りません。Hoard は両方の場所を探してゲーム単位で対応づけるので、Windows のセーブと Linux のセーブはひとつの履歴の二つのバージョンになります。

## Steam Cloud がすでにカバーしていること

Steam Cloud 対応の Steam ゲームなら、Steam が Windows のインストールと Proton のインストールの間でセーブを自分で同期します。そこで Hoard が加えるのは履歴です。Steam は現在のセーブしか持たないので、壊れたセーブが両方のシステムで正常なセーブを置き換えてしまいます。Steam Cloud のないゲームや Steam の外にあるものは、同期も Hoard が担います。

## Windows のドライブでフォルダーを共有すればいいのでは？

ほとんどの人が最初に思いつくのは、Linux から Windows パーティションのセーブを参照すれば済む、という方法です。たいてい三つの形で失敗します。

- **高速スタートアップと休止状態。** 高速スタートアップを有効にしたまま Windows をシャットダウンすると、パーティションが半ば休止状態のまま残り、Linux は読み取り専用でマウントするか、マウントを拒否します。ゲームはセーブを書き込めません。
- **Proton 上の NTFS。** NTFS ドライブから Proton のプレフィックスや Steam ライブラリを使うと、権限やファイル名の問題が起きやすいことで知られています。Linux のゲームは Linux のファイルシステムのほうが安定します。
- **リンクが置き換えられる。** 一方のシステムのセーブフォルダーをもう一方にシンボリックリンクする方法は、ゲームやアップデート、再インストールがリンクを本物のフォルダーに黙って置き換えるまでしか動きません。

それぞれのシステムがゲームの期待する場所にセーブを置き、その間を同期すれば、三つとも避けられます。

## 設定手順

1. **Windows で** Hoard をインストールしてサインインします。
2. **Linux で** [ダウンロードページ](/download) から Hoard をインストールし、同じアカウントでサインインします。
3. **Proton のゲームは Linux で一度ずつ起動して**、プレフィックスを作ってください。それまではセーブを置くフォルダーがありません。
4. 両方のシステムで **ライブラリ** を確認します。同じゲームがそれぞれに表示され、Hoard がゲーム単位で対応づけます。

## デュアルブートだけの落とし穴

別々の二台の PC なら、セーブはもう一台が取りに来るまでサーバーで待っています。デュアルブートでは「もう一台」は再起動後の同じコンピューターで、それによって習慣がひとつ変わります。

Hoard はゲームが閉じてフォルダーが落ち着いたところでセーブをアップロードします。**ゲームを終了してすぐに再起動すると、まだアップロードが済んでいないことがあり**、もう一方のシステムは最新の進行なしで起動します。次に最初のシステムを起動したときに追いつきますが、それまでに古いセーブで遊んでしまうかもしれません。

ですから、ゲームを終了したら少し待ち、アプリでセーブが最新になっていることを確認してから再起動してください。

## ネイティブ Linux 版

Windows 版とは別にネイティブの Linux 版があるゲームもあります。この二つは同じセーブ形式とは限らず、まったく別の場所に保存するものもあります。両方のシステムで同じセーブを使いたいなら、Linux でも Windows 版を Proton で動かすのがいちばん確実です。Steam で **プロパティ → 互換性** を開き、Proton のバージョンを強制してください。こうすれば両方のシステムが同じゲームを動かし、同じファイルを書きます。

## 設定とデバイス

グラフィック設定は二つのシステムで違うことがあるので、Hoard は `graphics.ini` のような設定ファイルをバックアップしますが、もう一方のシステムの設定に上書きはしません。それでもコピーしたい場合は、復元時にそのためのオプションがあります。

それぞれの OS が別のデバイスとして数えられるので、デュアルブートの PC は無料プランの三台のうち二台を使います。Pro とセルフホストのサーバーには台数の制限がありません。

セーブを家に置いておきたいなら、NAS か別のマシンで `hoard-server` を動かし、両方のシステムをそこに向けてください。私たちのアカウントは不要、私たちへのテレメトリーもなく、私たちのサーバーを何も通りません。[Hoard をセルフホストする方法](/guides/self-host-hoard) を参照してください。

## よくある質問

### Steam Cloud は Windows と Linux の間で同期しますか？

対応しているゲームなら、はい。どちらのシステムで遊んでも、Steam はアカウントごとにクラウドのコピーをひとつ持ちます。履歴はなく、Steam Cloud のないゲームや Steam の外にあるものはカバーしません。

### 共有の NTFS パーティションにセーブを置いてもいいですか？

おすすめしません。高速スタートアップで Linux からはパーティションが読み取り専用になることがあり、Proton は NTFS と相性が悪いことで知られています。各システムが自分の場所にセーブを置き、それを同期するほうが確実です。

### 再起動したらセーブがなかったのはなぜ？

おそらく再起動した時点でアップロードが終わっていませんでした。最初のシステムを起動し直し、Hoard にアップロードさせ、アプリで確認してから切り替えてください。

### デュアルブートの PC は一台として数えられますか？

いいえ、二台です。各 OS がそれぞれのデバイスとして登録されます。無料プランでは三台中の二台で、Pro とセルフホストのサーバーには制限がありません。

### ネイティブ Linux 版があるゲームは？

そのセーブは Windows 版のセーブと一致しないことがあります。セーブを共有するには、Linux でも Windows 版を Proton で動かしてください。
